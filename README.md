# Запись команд на кейсы хакатона

Простое приложение: команды выбирают кейс, на каждый кейс — лимит команд,
при заполнении запись закрывается. Статус мест обновляется в реальном времени.

## Что внутри

- `/` — лендинг с кейсами по трекам, live-счётчики мест, форма записи
- `/admin` — админка: сводка по кейсам, таблица записей, удаление, выгрузка CSV
- `cases.js` — конфиг кейсов (названия, описания, лимиты) — редактируется руками
- Данные хранятся в `data/signups.json` (папку можно вынести через `DATA_DIR`)

## Запуск локально

```bash
npm install
ADMIN_TOKEN=мой-секрет npm start
# http://localhost:3000        — лендинг
# http://localhost:3000/admin  — админка (введите токен)
```

## Деплой на Railway

1. Запушьте папку в GitHub-репозиторий (или используйте `railway up` через CLI).
2. В Railway: **New Project → Deploy from GitHub repo** — Railway сам поймёт Node.js.
3. В **Variables** добавьте `ADMIN_TOKEN` — придумайте длинный секрет.
4. **Важно:** чтобы записи не пропадали при редеплое, добавьте Volume:
   Service → Settings → Volumes → **Add Volume**, mount path `/data`,
   и переменную `DATA_DIR=/data`.
5. Settings → Networking → **Generate Domain** — получите публичную ссылку.

## Правка кейсов

Откройте `cases.js`: там массив кейсов с полями `id`, `track`, `title`,
`short` (краткое описание), `limit` (лимит команд), `detailUrl`
(ссылка на полное описание). После правки — редеплой.

## Надёжность

Node обрабатывает запросы в один поток, проверка лимита и запись происходят
атомарно — две команды не смогут занять одно последнее место даже при
одновременной отправке. 150–500 одновременных пользователей — не нагрузка
для этого приложения.
